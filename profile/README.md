## 🤝 협업 방식

### branch → PR → review → merge

최신 main에서 작업 브랜치를 만들고 변경을 push한 뒤, PR로 검토받습니다.

- **리뷰:** 작성자 외 쓰기 권한이 있는 팀원 1명 이상 승인, 리뷰 대화 해결, 필요한 CI 통과
- **병합:** 일반 **Merge commit** 사용 — Squash·Rebase 병합은 사용하지 않음
- **정리:** 작성자가 병합과 미반영 작업 여부를 확인한 뒤 작업 브랜치를 수동 삭제

> commit은 로컬 기록, push는 원격 업로드입니다. **main 반영은 PR 리뷰와 병합을 거칩니다.**

## 🧭 처음 합류했다면

1. **프로젝트 맥락 확인** — 상단 Notion에서 프로젝트 자료를 읽습니다. 접근 권한이 없다면 팀에 요청하세요.
2. **환경 준비** — Git 실전 가이드로 설정·인증을 준비하고, 작업할 저장소 README의 빌드·실행 방법을 확인합니다.
3. **작업 범위 합의** — 이슈에 담당자·작업 범위·완료 조건을 정리합니다.
4. **작은 PR부터 시작** — 변경과 검증 결과를 공유하고 리뷰를 요청합니다. 자세한 승인·병합 절차는 Git 실전 가이드를 따릅니다.
